# Paulice Web

A static web app that runs the [`qiskit-paulice`](../qiskit-paulice) spacetime
Pauli check picker in the browser via WebAssembly. Upload a Clifford circuit,
pick a device layout, choose the data qubits to protect, and run the check
picker — entirely client-side.

## What it does

1. **Circuit & layout** — paste/upload an OpenQASM 2.0 Clifford circuit and pick
   a device connectivity (IBM preset, line/grid, or custom coupling map). Both
   the circuit and the device graph are rendered as SVG.
2. **Data qubits & noise** — click qubits (in the graph or the checkbox list) to
   choose which data qubits host checks, set a uniform depolarizing rate
   (optional readout rate), and a seed.
3. **Run & results** — the windowed search runs in a Web Worker; browse the
   cost-vs-#checks variants (with a Γ-vs-checks recap chart), view the checked
   circuit, copy/download it as QASM, or **open it in the 3D circuit viewer**.

### 3D viewer link

The **Open in 3D viewer ↗** button deep-links the selected variant to
[3dcircuit](https://smartiel.github.io/3dcircuit) by carrying the QASM and a
layout file in the URL fragment (`#qasm=…&layout=…`, percent-encoded — the
fragment never hits a server, so large circuits are fine). The layout places
payload qubits at their device coordinates and each check ancilla next to its
target. The viewer reads these on load (see its `#qasm=…&layout=…` hash hook).

First release scope: `method="windowed"`, `cost="gamma"`, uniform depolarizing
noise (+ optional readout). Serial (single-threaded) wasm — no special hosting
headers required.

## Architecture

The check-picking **primitives** (`CheckPicker`, `Metric`, `NoiseModel`) are the
same Rust core the Python package uses, compiled to wasm via `wasm-bindgen`
(see `../qiskit-paulice/src/wasm_interface.rs`, behind the crate's `wasm`
feature). The **orchestration** that Python implements (`CheckPickerStation`,
the windowed search, circuit conversion, layout graph logic) is re-implemented
in TypeScript against that wasm surface:

```
src/
  wasm/            generated by wasm-pack (see below)
  qasm/            OpenQASM 2.0 parser + exporter
  core/            convert (rustiq <-> internal), station, windowed, pickChecks, rng
  layout/          coupling-map presets/generators + getCheckQubits (layout.py port)
  ui/              SVG circuit renderer + device connectivity graph
  worker.ts        runs pickChecks off the main thread
  main.ts          3-step UI flow
```

## Build

Requires **Node 18+** and the Rust wasm toolchain (`rustup target add
wasm32-unknown-unknown`, `wasm-pack`).

```bash
# 1. Build the wasm core into src/wasm/ (run from repo root or via npm script).
npm run wasm            # == bash ../build-wasm.sh

# 2. Install JS deps.
npm install

# 3a. Dev server.
npm run dev

# 3b. Production static build -> dist/ (deployable to any static host).
npm run build

# Tests (unit + a headless wasm end-to-end test; needs step 1 done first).
npm test
```

> The wasm artifacts in `src/wasm/` are generated; if they're missing, run
> `npm run wasm` before `npm run dev`/`build`/`test`.

## Deploy to GitHub Pages

The site is fully static (`base: "./"` → relative asset URLs, so it works at any
Pages subpath, e.g. `https://<user>.github.io/<repo>/`).

**Recommended (CI):** the repo ships `.github/workflows/deploy.yml`, which builds
the wasm bundle and the site on every push to `main`, then publishes to Pages.
To enable it:

1. Push the repo (containing `qiskit-paulice/`, `web/`, and `build-wasm.sh`) to
   GitHub with the default branch named `main`.
2. In the repo, go to **Settings → Pages → Build and deployment → Source** and
   select **GitHub Actions**.
3. Push to `main` (or run the workflow manually). The site deploys to
   `https://<user>.github.io/<repo>/`.

**Manual (no CI):** build locally and publish the `dist/` folder:

```bash
npm run wasm && npm ci && npm run build   # produces web/dist/
```

Then commit `web/dist/` to a `gh-pages` branch (or a `docs/` folder) and point
**Settings → Pages** at it. Because asset URLs are relative, no base-path config
is needed.

## Notes / limitations

- Non-ISA picking: the picker appends ancillas at the end of the qubit list; the
  device layout is used to suggest hardware ancilla pairings (informational) and
  to select data qubits.
- Only Clifford circuits are supported (basis: `h, s, sdg, sx, sxdg, x, z, cx,
  cz`, and `rz`/`u1` at multiples of π/2). The circuit must end with at least one
  measurement.
- Determinism: a fixed seed makes a run reproducible in-app. Exact numerical
  parity with the Python (NumPy-seeded) implementation is not attempted.
- Follow-ups: genetic / windowed-genetic methods, LER cost, and gate-wise /
  layered noise (all supported by the core; just need TS wiring).
